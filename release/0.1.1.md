# ModAVDExtras v0.1.1

- `modavd_extras.dll`：`95b09e1c295f83eb4ae3f11555b6b0954f1db6f989bd669a7a2ef6d4a97ba015`
- `external_renderer_ipc.dll`：`ae9c582e29bebacd12b66c34743775ba58a0f5271cf3ed8732e77b3137bb6f34`

修正一处截图的返回值。附件照旧是 Windows x64 的两个 DLL；接口版本还是 1，头文件只改了注释，调用方不用重编。

## 改了什么

- `modavd_extras.dll`：拷贝途中次次来新帧时，`modavd_capture` 返回 `MODAVD_E_NOT_READY`（#6）。
  - 模拟器写截图共享内存不加锁，库拷完比一下帧号，变了就重拷，连第一次最多拷 3 次。v0.1.0 里 3 次都撞上新帧也返回 `MODAVD_OK`，交出去的图可能是两帧拼起来的。现在返回 `MODAVD_E_NOT_READY` 并记一条警告，再截一次就行。
  - 没有新的出错码：`MODAVD_E_NOT_READY` 原来表示截图共享没开、还没有画面，现在也包括这种情况。
  - 实际很难碰到：拷一帧约 0.1 ms，模拟器约 16 ms 写一帧。
- `external_renderer_ipc.dll`：行为不变。这种情况下照旧把最后一次拷贝交出去、返回成功，和它替换的 DLL 一样，因为 MaaCore 的 MuMu 那条路截图一失败就会重新测速。
- 转换代码没动，BGR 按 16 像素一块转换的提速已在 v0.1.0 里。`modavd_version_string()` 返回 `"0.1.1"`。
- 其余同 [v0.1.0](https://github.com/ModAVD/ModAVDExtras/releases/tag/v0.1.0)：两个 DLL 都静态链接 C 运行库，只依赖 `KERNEL32`、`WS2_32`。

## English

A fix to one capture return value. As before, the release attaches the two Windows x64 DLLs; the API version is still 1 and only comments changed in the header, so callers need not rebuild.

- `modavd_extras.dll`: `modavd_capture` returns `MODAVD_E_NOT_READY` when a new frame arrives during every copy (#6). The emulator writes the frame-sharing memory without a lock, so the library compares the frame number around each copy and copies again when it changed, up to 3 copies in all. In v0.1.0 it returned `MODAVD_OK` even when all 3 copies were overtaken, and the frame handed back could mix two frames. It now returns `MODAVD_E_NOT_READY` and logs a warning; call again. There is no new error code: `MODAVD_E_NOT_READY` already meant frame sharing is off or no frame was composed yet, and now covers this case too. It is rare in practice: a copy takes about 0.1 ms and the emulator writes a frame about every 16 ms.
- `external_renderer_ipc.dll`: unchanged behaviour. In this case it still hands over the last copy and returns success, as the DLL it replaces did, because MaaCore's MuMu path drops back to its screencap speed test after a failed capture.
- The conversion code is unchanged; the 16-pixel BGR conversion is already in v0.1.0. `modavd_version_string()` returns `"0.1.1"`.
- Everything else is as in [v0.1.0](https://github.com/ModAVD/ModAVDExtras/releases/tag/v0.1.0): both DLLs link the C runtime statically and depend only on `KERNEL32` and `WS2_32`.
