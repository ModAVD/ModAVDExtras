# ModAVDExtras v0.1.3

- `modavd_extras.dll`：`5ea1f80b23537886b05503e441691956d34381c93efe7b664777bd85bd653cdb`
- `external_renderer_ipc.dll`：`0fecc13ef0064ac8cf4e65934b75c32a555d6e7d50490ed84947b1eff7221acc`
- `libmodavd_extras.dylib`：`df53353f70adfe48853626fda103eb82197fa94d3caaf019f861787204467e53`
- `libmodavd_extras.so`：`df76579f3b6f583eed78650d28ea11aea69fadbf934dcfc79c73c84e5321c8e8`

这一版只改 MuMu 外壳 `external_renderer_ipc.dll`：在 MAA 里填的实例编号直接就是 ModAVD 的编号，根目录改过端口段也不用自己算端口。截图库本身行为不变，接口版本还是 1。

## 变更

- `external_renderer_ipc.dll`：收到小于 5554 的 `index` 时当成 ModAVD 的实例编号，控制台端口按外壳所在根目录 `mas-avd.json` 的 `portBase` 算（`portBase + 10×编号`）（#12）。
  - ModAVD 包会把外壳放在 `<根目录>\mumu-shim\shell\sdk\`；MAA 的 MuMu 路径填 `<根目录>\mumu-shim`，外壳从 MuMu 路径的上一级读 `mas-avd.json`。
  - `portBase` 读不到、或者不是 1100–65400 之间 100 的整数倍，照旧按 20000 算。
  - 控制台端口（≥ 5554）照旧原样认。
- `modavd_version_string()` 返回 `"0.1.3"`。

## 下载与核对

四个文件都由本仓库的 release workflow 在 GitHub 上编出，和 tag 下的 `release/0.1.3.SHA256SUMS.txt` 核对过才上传。编译环境和 v0.1.2 一样：

## English

This release only changes the MuMu shim `external_renderer_ipc.dll`: the instance index entered in MAA is the ModAVD instance index, and a root with its own port range needs no port arithmetic. The capture library itself is unchanged; the API version is still 1.

- `external_renderer_ipc.dll`: an `index` below 5554 is taken as a ModAVD instance index, and the console port is `portBase + 10 × index`, with `portBase` read from `mas-avd.json` in the root the shim sits in (#12). The ModAVD package puts the shim in `<root>\mumu-shim\shell\sdk\`; MAA's MuMu path is `<root>\mumu-shim`, and the shim reads `mas-avd.json` one level above it. Without a valid `portBase` (a multiple of 100 between 1100 and 65400) it uses 20000 as before. Console ports (5554 and above) are still taken as they are.
