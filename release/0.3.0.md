# ModAVDExtras v0.3.0

- `modavd_extras.dll`：`4837c513ab4eb8a6393d2312163d4c1bffaf17fc1f7099208b1df0856d155b88`
- `external_renderer_ipc.dll`：`ee0cbaff8e96f82c03e72b292e5e999afe4b4d0486c1494757798273bb1b4b61`
- `libmodavd_extras.dylib`：`406813a35f504492b59a290a86612a0f235592cc57bbccefa1d8cfdcedf4ff10`
- `libmodavd_extras.so`：`41bae8333146f59f1e5c08c579924a364ead38e74d149e8388cea04834fdac02`

这一版加上按键和输入文字：`modavd_key`、`modavd_input_text` 能用了，接口版本升到 3。截图、点击和 MuMu 外壳的行为不变。

## 新增

- 输入文字（`MODAVD_CAP_TEXT`）：`modavd_input_text`，UTF-8（#19）。
  - 编辑框有焦点、ModAVD 的宿主输入法（`org.modavd.ime`）在用时，文字原样交给编辑框，任意语言；换行发成回车键。
  - 否则，可打印的 ASCII 由模拟器的键盘打出来，约 1.2 ms 一个字符。
  - 两样都不满足（不是 ASCII，又没有这样的编辑框）时返回 `MODAVD_E_UNSUPPORTED`，什么都不打。
- 按键（`MODAVD_CAP_KEY`）：`modavd_key`，安卓 KEYCODE（#19）。
  - 模拟器的控制台有 `event key` 时，按的是模拟器键盘上的真实按键，按下、抬起分开发，返回、主页、多任务也在内。这条命令要比 ModAVD 0.40 新的模拟器，那时才有 `MODAVD_CAP_KEY`。
  - ModAVD 0.40 的模拟器上：能打出字符的键（字母、数字、回车、Tab、空格、标点）可用；编辑键（退格、方向键等）在编辑框有焦点时可用；其余返回 `MODAVD_E_UNSUPPORTED`。这两条路按下时就把按下和抬起一起发了。
  - Esc 键被模拟器键盘的键位表读作返回。
- `modavd_api_version()` 返回 3，`modavd_capabilities()` 多了 `MODAVD_CAP_TEXT`（接口版本 3 起恒有）和 `MODAVD_CAP_KEY`（控制台有 `event key` 时才有）。
- `modavd_version_string()` 返回 `"0.3.0"`。

## 说明

- `modavd_capabilities()` 第一次调用会连一次模拟器控制台，用来判断有没有 `event key`。
- 和点击一样不经 adb，客体里不用装东西；库不自己退回 adb，做不了时返回错误码，由调用方换别的办法。
- 只认接口版本 1、2 的程序不受影响：原有函数和行为都没变。
- `external_renderer_ipc.dll` 的源码没改，但它静态链接了库的代码，所以文件和 v0.2.0 不一样。
- Linux、macOS 上按键和文字只过了编译和单元测试，没有在模拟器上实测。

## English

This release adds keys and text: `modavd_key` and `modavd_input_text` now work, and the API version is 3. Capture, touch and the MuMu shim behave as before.

- Text (`MODAVD_CAP_TEXT`): `modavd_input_text`, UTF-8 (#19). With a focused text field and ModAVD's host input method (`org.modavd.ime`) active, the text is handed to the field as is, in any language, and a newline is sent as ENTER. Otherwise printable ASCII is typed on the emulator's keyboard, about 1.2 ms per character. When neither applies it returns `MODAVD_E_UNSUPPORTED` and types nothing.
- Keys (`MODAVD_CAP_KEY`): `modavd_key`, Android key codes (#19). When the emulator console has `event key`, real keys of the emulator's keyboard are pressed, down and up sent separately, BACK, HOME and APP_SWITCH included; that needs an emulator newer than ModAVD 0.40, and only then is `MODAVD_CAP_KEY` set. On ModAVD 0.40 emulators, keys that type a character work, editing keys (DEL, arrows) work in a focused text field, and the rest return `MODAVD_E_UNSUPPORTED`; on those two paths the press sends down and up together. The emulator keyboard's layout reads Esc as BACK.
- `modavd_api_version()` returns 3; `modavd_capabilities()` adds `MODAVD_CAP_TEXT` (always, from API version 3) and `MODAVD_CAP_KEY` (when the console has `event key`), and its first call opens a console session once. `modavd_version_string()` returns `"0.3.0"`.
- Functions of API versions 1 and 2 are unchanged. `external_renderer_ipc.dll` has no source changes, but it links the library code statically, so the file differs from v0.2.0. On Linux and macOS, keys and text are only built and unit-tested, not tested with an emulator.
