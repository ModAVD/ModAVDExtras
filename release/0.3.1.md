# ModAVDExtras v0.3.1

- `modavd_extras.dll`：`待 CI 编出后填`
- `external_renderer_ipc.dll`：`待 CI 编出后填`
- `libmodavd_extras.dylib`：`待 CI 编出后填`
- `libmodavd_extras.so`：`待 CI 编出后填`

这一版修复 Windows 上模拟器退出后截图共享内存不放的问题（ModAVD/ModAVD#210）。没有新增函数，接口版本还是 3；只是 `modavd_open`、`modavd_capture` 在 Windows 上多了几种返回 `MODAVD_E_NOT_FOUND` 的情况。

## 变更

- Windows：模拟器退出后放掉截图共享内存，同一端口的下一台模拟器起来时自己重新映射（#22）。
  - 以前句柄一直映射着旧的那块，模拟器退出了也不放；同一端口的下一台（比如改成 1080p 后）再建共享内存时，拿回来的还是旧的、更小的那块，映射失败，截图共享就开不起来。
  - 打开时找出监听控制台端口的进程（就是模拟器），等它退出时关掉映射。
  - `modavd_capture` 遇到映射已经没了，最多每秒试一次映射当前这台模拟器的共享内存，没有就返回 `MODAVD_E_NOT_FOUND`，过一会儿再调就行，句柄会自己映射下一台的。
  - `modavd_open` 普通打开时，共享内存在、控制台端口却没人监听，说明是别的程序留着的旧的：不映射，返回 `MODAVD_E_NOT_FOUND`。带 `MODAVD_OPEN_NO_START` 的照旧信任现有映射。
  - MuMu 形状的外壳 `external_renderer_ipc.dll` 走同一条抓图路径。
- `include/modavd_extras.h` 补上了上面这些返回值的说明。
- `modavd_version_string()` 返回 `"0.3.1"`。

## 说明

- 点击、按键、文字的行为没变；Linux、macOS 的代码没变。
- 两个 Windows DLL 的字节都变了：库的代码改了，外壳静态链接着它。

## English

This release fixes the screenshot shared memory not being released on Windows after the emulator exits (ModAVD/ModAVD#210). No functions were added and the API version is still 3; `modavd_open` and `modavd_capture` just return `MODAVD_E_NOT_FOUND` in a few more cases on Windows.

- Windows: the mapping is released when the emulator exits, and the next emulator on the same port is mapped by the handle itself (#22). Before, the handle kept the old region mapped; the next emulator on the port (for example after switching to 1080p) got the old, smaller region back and the mapping failed, so frame sharing could not start.
- The handle finds the process listening on the console port (the emulator) and closes the mapping when it exits. If the mapping is gone, `modavd_capture` tries to map the current emulator's region at most once a second and returns `MODAVD_E_NOT_FOUND` while there is none; call again later.
- A plain `modavd_open` with a region present but nothing listening on the console port treats the region as left over by another program: it does not map it and returns `MODAVD_E_NOT_FOUND`. With `MODAVD_OPEN_NO_START` the existing mapping is trusted as before.
- The MuMu-shaped shim `external_renderer_ipc.dll` uses the same capture path. `include/modavd_extras.h` documents the return values. `modavd_version_string()` returns `"0.3.1"`.
- Touch, keys and text behave as before; the Linux and macOS code is unchanged. Both Windows DLLs differ from v0.3.0.
